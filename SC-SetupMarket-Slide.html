What SC-Setup automates

End-to-end flow

🔐 Certificates

Installs trust material and imports application certificates when required.

📁 Git checkout & build

Clones market repositories, selects branches, and can trigger local builds.

⚙ Config generation

Generates local files, Java options, and application configuration from SCM payloads.

🔗 Environment wiring

Applies environment URLs, keystores, truststores, and market-specific overrides.

☕ Runtime bootstrap

Downloads or reuses JDK, Maven, and Tomcat from existing local caches.

🐱 Tomcat preparation

Prepares startup scripts, context files, logging configuration, and runner assets.

How the runtime flow works

Technical overview
1

Load installer profile

Read the selected Groovy profile and load its setup rules, runtime settings, and lifecycle actions.

2

Prepare SCM trust

Fetch the SCM Tool certificates and install them into the local JDK trust store so the app can connect securely.

3

Prepare tools

Download or reuse JDK, Tomcat, and Maven, then prepare the local runtime folders.

4

Pull SCM configuration

Download secrets and config maps, decode them, and turn them into local runtime inputs.

5

Generate local startup

Create the scripts, properties, context files, and logging overlays needed to run locally.

What gets produced locally

One extra advantage is that Tomcat can run outside IntelliJ, which keeps the startup path independent from IDE-specific settings, makes the setup easier to reproduce on another machine, and is closer to real container-style startup.
